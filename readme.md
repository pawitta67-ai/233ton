# ระบบคอร์สแวร์ การออกแบบอินโฟกราฟิก (ง31241) - AR Courseware

ระบบบทเรียนคอมพิวเตอร์ช่วยสอน (CAI) แบบ Serverless (Client-side rendering) สำหรับรายวิชาการออกแบบอินโฟกราฟิก ระดับชั้นมัธยมศึกษาปีที่ 4 โรงเรียนชุมชนนาเต่าสุขสวรรค์ (ประชาราษฎร์ 347) โดยใช้ HTML/JS ล้วนในส่วนหน้าบ้าน (Frontend) และใช้ Supabase (PostgreSQL) เป็นระบบหลังบ้าน (Backend)

## 📁 โครงสร้างไฟล์
1. `setup.sql` - สคริปต์ตั้งค่าฐานข้อมูล สร้างตาราง, RLS Policies, Functions, Triggers และ Storage (รันเพียงครั้งเดียว)
2. `courseware.html` - ไฟล์ระบบหลัก มี UI, เนื้อหาบทเรียน, ข้อสอบ และระบบจัดการผู้เรียน/ผู้สอน
3. `README.md` - คู่มือการติดตั้งและทดสอบระบบไฟล์นี้

## ⚙️ คู่มือการติดตั้ง (Installation Guide)

ผู้ที่ไม่ใช่โปรแกรมเมอร์สามารถทำตามขั้นตอนเหล่านี้ได้เพื่อเปิดใช้งานระบบ:

1. **สร้างฐานข้อมูล:** สมัครใช้งานฟรีที่ [supabase.com](https://supabase.com) สร้างโปรเจกต์ใหม่ (จดรหัสผ่าน Database ไว้) รอจนระบบสร้างโปรเจกต์เสร็จ
2. **ปิดการยืนยันอีเมล:** ไปที่เมนู **Authentication** (รูปผู้ใช้) > **Providers** > เลือก **Email** > ปิดสวิตช์ "Confirm email" แล้วกด Save
3. **รันคำสั่งฐานข้อมูล:** ไปที่เมนู **SQL Editor** (รูป `</>` ด้านซ้าย) วางโค้ดจากไฟล์ `setup.sql` ทั้งหมดลงไป แล้วกดปุ่ม **Run**
4. **เตรียมข้อมูลเชื่อมต่อ:** ไปที่ไอคอนรูปเฟือง (**Project Settings**) > เลือก **API** > คัดลอกค่า **Project URL** และ **anon / public key**
5. **ใส่ค่าในหน้าเว็บ:** เปิดไฟล์ `courseware.html` ด้วยโปรแกรม Text Editor (เช่น Notepad) ค้นหาตัวแปร `SUPABASE_URL` และ `SUPABASE_ANON_KEY` นำค่าที่ได้จากข้อ 4 มาวางในเครื่องหมายคำพูด แล้วกดบันทึก
6. **สร้างบัญชีผู้สอน:** เปิดไฟล์ `courseware.html` ด้วยเว็บเบราว์เซอร์ สมัครสมาชิกด้วยอีเมลของคุณเอง (เช่น `teacher@school.ac.th` ห้ามขึ้นต้นด้วยตัวเลข 11 หลัก)
7. **คัดลอก UID ผู้สอน:** กลับไปที่ระบบ Supabase > เมนู **Authentication** > หาอีเมลของคุณที่เพิ่งสมัคร แล้วคัดลอกค่า **User UID**
8. **ตั้งสิทธิ์ผู้สอน:** ไปที่ **SQL Editor** วางคำสั่ง `INSERT INTO teachers (user_id) VALUES ('ใส่-UID-ที่นี่');` แล้วกด Run
9. **เพิ่มรายชื่อนักเรียน:** ไปที่ **Table Editor** > ตาราง `students` นำเข้าข้อมูลนักเรียนด้วยไฟล์ CSV (หัวคอลัมน์: `id`, `title`, `first_name`, `last_name`, `section`) หรือเพิ่มด้วยมือ
10. **พร้อมใช้งาน:** ส่งไฟล์ `courseware.html` ให้นักเรียนใช้งาน หรือนำไฟล์ไปฝากไว้บนเว็บโฮสติ้งฟรี (เช่น GitHub Pages)

## 🧪 แบบทดสอบระบบ (System Test Plan)

รายการทดสอบเพื่อยืนยันว่าระบบและนโยบายความปลอดภัย (RLS) ทำงานได้อย่างถูกต้อง:

| ข้อ | ผู้กระทำ | การกระทำ | ผลลัพธ์ที่ควรเกิดขึ้น |
|:---:|:---|:---|:---|
| 1 | นักเรียน | สมัครด้วยอีเมลที่ไม่ขึ้นต้นด้วยเลข 11 หลัก | ระบบปฏิเสธ: "ไม่พบรหัสนักศึกษานี้ในรายวิชา" |
| 2 | นักเรียน | สมัครด้วยรหัส 11 หลักที่ไม่มีในตาราง `students` | ระบบปฏิเสธ: "ไม่พบรหัสนักศึกษานี้ในรายวิชา" |
| 3 | นักเรียน | สมัครด้วยรหัส 11 หลักที่ถูกต้อง (มีในฐานข้อมูล) | สมัครสำเร็จ และเข้าสู่หน้าแดชบอร์ดบทเรียน |
| 4 | นักเรียน | สมัครด้วยรหัสที่คนอื่นสมัครไปแล้ว | ระบบปฏิเสธ: "รหัสนักศึกษานี้ถูกลงทะเบียนไปแล้ว" |
| 5 | ผู้สอน | เข้าสู่ระบบด้วยอีเมลที่ถูกตั้งสิทธิ์ไว้ | เห็นหน้าแดชบอร์ดสรุปผลคะแนนของนักเรียนทุกคน |
| 6 | นักเรียน | พยายามเข้าถึงข้อมูลของนักเรียนคนอื่น (ผ่าน API) | ไม่แสดงผล (Row Level Security ป้องกันไว้) |
| 7 | นักเรียน | ส่งงานปฏิบัติ (ไฟล์ pdf หรือวิดีโอ) ขนาดไม่เกิน 20MB | อัปโหลดสำเร็จ สถานะใน `submissions` อัปเดต |
| 8 | นักเรียน | อัปโหลดไฟล์ขนาดใหญ่เกิน 20MB | อัปโหลดล้มเหลว ระบบแจ้งเตือนไฟล์ขนาดเกิน |
| 9 | นักเรียน | พยายามแฮ็กแก้คะแนน `score` ตัวเองผ่าน API | ฐานข้อมูลจะคืนค่าคะแนนเดิมกลับไปอัตโนมัติ (Trigger ป้องกัน) |
| 10 | นักเรียน | พยายามลบสื่อการสอนของผู้สอน | ทำไม่ได้ (RLS ป้องกัน) ระบบแจ้งข้อผิดพลาด |
| 11 | ผู้สอน | อัปโหลดสื่อการสอน (pdf, pptx) | ไฟล์ขึ้นระบบ ผู้เรียนทุกคนมองเห็นและดาวน์โหลดได้ |
| 12 | นักเรียน | ทำแบบทดสอบก่อนเรียน แล้วคลิกทำซ้ำ | ทำซ้ำไม่ได้ ปุ่มเข้าทำจะถูกล็อก/API ปฏิเสธการบันทึกซ้ำ |
| 13 | ผู้สอน | ตรวจงานและพิมพ์ข้อเสนอแนะ | ข้อมูลบันทึกลง `submissions` นักเรียนเห็นคะแนนทันที |
| 14 | ผู้สอน | กดปุ่ม Export สรุปผลคะแนน | ดาวน์โหลดไฟล์ `results.csv` ที่เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน (มี BOM) |

## ⚠️ รายการที่ผู้สอนต้องตรวจสอบก่อนใช้งานจริง

1. **เนื้อหาและข้อสอบ:** กรุณาตรวจสอบความถูกต้องของเนื้อหาบทเรียนและเฉลยข้อสอบในไฟล์ `courseware.html` ให้ตรงกับแผนการสอน
2. **แหล่งอ้างอิงวิชาการ:** มีการใช้ทฤษฎีของ *Mayer* ในหน่วยที่ 3 กรุณาเติมปี ค.ศ. ที่ตีพิมพ์ (เช่น 2009 หรือ 2014) ในเนื้อหาหากจำเป็น
3. **ข้อจำกัดของ AR:** ระบบใช้ `<model-viewer>` ของ Google อุปกรณ์ของผู้เรียนต้องมีการเชื่อมต่ออินเทอร์เน็ตที่เสถียร และประสิทธิภาพของ AR จะขึ้นอยู่กับสเปกเซนเซอร์ของสมาร์ทโฟนผู้เรียน
